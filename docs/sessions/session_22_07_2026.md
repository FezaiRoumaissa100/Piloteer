# Session du 22/07/2026

## Résumé des modifications dans le code (Implémentation)

Aujourd'hui, nous avons intégré le concept de **"Scope-Aware Recovery"** (Récupération consciente du périmètre) pour le planificateur de haut niveau. Cela permet à l'agent de juger si un échec nécessite une simple correction locale ou une révision complète du reste du plan.

### Fichiers modifiés :

#### 1. `src/prompts/high_level_planner_prompt.py`
- Mise à jour majeure du prompt système `REVISE_SYSTEM_PROMPT`.
- Ajout de la règle explicite obligeant le LLM à définir le périmètre de l'erreur via la clé `"scope"` (`"local"` ou `"downstream"`).
- Modification du schéma JSON de sortie pour inclure les nouvelles clés : `diagnosis`, `scope`, `revised_current`, et `revised_downstream`.
- Uniformisation linguistique des exemples de JSON pour utiliser systématiquement la formulation d'état final "must be" (ex: `"The blocking dropdown menu must be closed."`).

#### 2. `src/nodes/high_level_planner.py`
- Modification de la logique Python dans le `Mode 2` (Révision lors d'une escalade).
- Ajout du parsing et de la gestion de la variable `"scope"`.
- Implémentation du comportement de réécriture globale (downstream) :
  - Si `scope == "downstream"`, le script efface automatiquement tous les sous-objectifs restants via un troncage de la liste (`updated_subgoals[:current_index + 1]`).
  - Le script boucle ensuite sur la liste `revised_downstream` générée par le LLM pour injecter les nouveaux sous-objectifs dans la file d'attente avec un statut `"pending"`.
- Ajout d'une condition de repli (fallback) de sécurité pour traiter la clé `"revised_description"` au cas où le modèle hallucinerait l'ancien format.
